# Ритм — Telegram Mini App

Тёмный адаптивный интерфейс трекера привычек. Это первый работающий прототип:

- привычки можно создавать, отмечать выполненными и удалять;
- прогресс и список сохраняются в браузере на этом устройстве;
- Telegram Mini App API используется для безопасных отступов, цвета интерфейса и имени пользователя;
- сервер проверяет подпись Telegram `initData` и передаёт события в Make.com, не раскрывая URL вебхука в браузере.

## Запуск локального прототипа

Нужен Python 3.10+; зависимости устанавливать не нужно.

```powershell
python server.py
```

Открой `http://localhost:8000`. В обычном браузере интерфейс и локальное сохранение доступны, но Make.com-события начнут отправляться только после настройки переменных окружения и открытия приложения через Telegram.

## Подключение Telegram Mini App

1. Размести приложение на публичном HTTPS-хостинге, который умеет запускать `python server.py`.
2. В настройках хостинга добавь `TELEGRAM_BOT_TOKEN` — токен, полученный в BotFather. Не отправляй его в чат и не сохраняй в `app.js`.
3. В BotFather настрой Menu Button / Web App URL на HTTPS-адрес приложения.
4. Открой приложение через кнопку меню в Telegram. Сервер проверяет подпись `initData` на каждом событии, срок данных ограничен 24 часами.

## Make.com: один сценарий для привычек

В коде уже готовы события `habit.created`, `habit.completed`, `habit.uncompleted` и `habit.deleted`. В Make создай сценарий:

1. **Webhooks → Custom webhook** и скопируй URL созданного вебхука.
2. Добавь URL как серверную переменную `MAKE_WEBHOOK_URL` на хостинге. Не добавляй его в JavaScript или публичный репозиторий.
3. Нажми **Run once**, создай привычку в Mini App и отметь её выполненной, чтобы Make получил пример структуры данных.
4. Добавь Router с двумя ветками и фильтрами по `event`:
   - `habit.created`: записать привычку в Make Data Store с ключом `user.id:habit.id`;
   - `habit.completed`: обновить отметку выполнения для этой привычки и пользователя.
5. Для `habit.uncompleted` сними отметку текущего дня; для `habit.deleted` удали запись привычки.
6. Для идемпотентности храни дату выполнения отдельно и не создавай повторную отметку за тот же день.
7. Включи сценарий и проверь все типы событий.

Пример входящего события:

```json
{
  "event": "habit.completed",
  "user": { "id": 123456789, "first_name": "Аня" },
  "habit": { "id": "water", "title": "Выпить стакан воды", "icon": "◌" },
  "occurred_at": 1790000000
}
```

> Сейчас Make.com получает события, а состояние интерфейса хранится локально в браузере. Это не синхронизация между устройствами. Для общей истории привычек нужен следующий шаг: хранение и выдача записей с сервера/базы данных (можно построить в Make, но сценарии чтения и записи нужно отдельно спроектировать).

## MCP и Make.com

MCP — это способ подключить инструменты к AI-клиенту; он не нужен, чтобы Mini App отправлял события. Для приложения используется Make Custom Webhook. Если нужно управлять сценариями Make из MCP-клиента, настрой MCP-коннектор Make отдельно в самом AI-клиенте и выдавай ему только необходимые права. Не помещай MCP-секреты или ключи Make в клиентские файлы.

## Перед публикацией

- Настроить HTTPS и переменные `TELEGRAM_BOT_TOKEN` / `MAKE_WEBHOOK_URL` у хостинг-провайдера.
- Подключить постоянное хранилище, если нужна синхронизация и история выполнений между устройствами.
- Проверить внешний вид внутри Telegram на iOS и Android.
